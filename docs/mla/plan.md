# MLA 迭代计划

本页只记录实施顺序、产物和完成条件。**非量化 M17、已授权的 INT8 M18–M21、R4 测试整理及 R5 E2E 组合精简与数值修复均已完成；当前无待开发步骤。** 用户于 2026-10-18 批准 M18–M21 的 INT8 扩展；范围以 [design 3.4](design.md#34-int8-压缩-mla-扩展) 为准，当前能力、限制和证据以 [status](status.md) 为准。2026-10-19 的 INT8 授权为图模式性能暂不做要求，适用于 M19–M21；同日用户确认 R5 记录既有默认路径性能差距后提交。两项例外的边界分别见 design 3.4 和第 7 节。

## R5：公开 E2E 组合精简与数值修复（已完成）

用户于 2026-10-19 确认精简 R4 的 1,814 项用例，并补充要求：功能组合完整，每个组合减少重复输入，保留回归看护。原范围为 `tests/test_flash_attn_npu_v3_mla.py` 的参数化和用例选择及对应文档；完整实测检出稳定数值错误后，用户明确确认本轮同时修复并重建验证。公共 conftest、独立 reference、断言、阈值、CI 和构建配方不改，不设置数量截断、随机采样或额外测试框架。

- 前向主矩阵完整展开五布局 × 两种表示 × 双 dtype × 三 mask × 自动/单/显式 split × softcap 关/开，每组合一个代表输入；softcap 开启时选用已有 saturation 输入，使截断效果可观察。32 个旧场景的覆盖目的分别并入主矩阵或具名边界表。全局空 B/Q/KV、显式 packed/unpacked 仍跨全部布局/表示/dtype；其他窗口取值、数值极值、长 KV、尾块在对应布局保留双表示/双 dtype。
- GQA 保留 MQA/MHA/GQA、最小/最大头数及非二次幂 KV 头，页大小保留最小、非二次幂、常用和大页，减少同一类别的取值。stride、fake/compile、图模式、生命周期与动态长度组合全部保留。共享标量拒绝检查减少跨入口重复，但保留每种错误、两种表示、real/fake 及入口分派拒绝；长度/metadata 的存储形式和 grad 拒绝使用代表 dtype，数值主矩阵仍覆盖双 dtype。
- INT8 的数值、长 KV/连续空尾段、scale/stride、空值、real/fake 拒绝、compile、图模式及冷捕获全部保留，不套用非量化选项矩阵。

验收先核对 `7ea2bca` 的 JUnit、完整收集清单、源文件和已加载扩展；在仓库外 `mla-test-pruning/` 记录按函数的新旧数量及保留目的。先 `python3 -m pytest --collect-only -q tests/test_flash_attn_npu_v3_mla.py`，核对主矩阵完整性、旧场景覆盖映射、错误类型、INT8/图集合无删减及参数表去重；再实跑前向边界与 real/fake/compile/图代表，最后固定实现运行完整精简集合，保存 JUnit 和耗时。reference 算法与执行策略未变，继承 R4 的最大内存/最长 reference 成本边界；生产数值修复后重新运行 R4 的 140 项普通 FA3 相关回归，明确其是选跑子集。本轮 MLA 必须实际执行，不能把旧节点通过算作新结果。

补充看护检查：在仓库外使用同一公开调用与独立 reference，故意忽略 softcap 或 mask，确认代表组合触发数值断言；仅改变临时调用参数，不改生产源码，不计作正常通过用例。完成条件：核心功能组合完整、独立边界无缺失，同一组合的重复输入减少，新完整集合通过，记录数量/耗时和覆盖差异；文档链接、仓库 pre-commit 与 `git diff --check` 通过后提交一次并停止。失败或必要验证受限时保留 R5 交接。

**本轮数值修复的影响与验收。** 原主矩阵 `window-no-softcap-single-mixed-compressed-bf16`（固定种子 880500170，Q=(3,1)、KV=(1057,513)、Hq=8）稳定出现一个非零输出被写成 0；同输入对照 TND 单片也失败，自动/显式 split 与分页正常，metadata 有无不影响。根因为共用 Vector 对精确零 PV 执行负 int32 位修正，产生 NaN 后被输出保护清零。保留原输入及种子，修复在 UB 执行同一位加法并保留原零值，补齐临时存储读写同步；复用现有缓冲和跨核协议。输入 helper 增加确定性的块内抵消模式，新增五布局 × 双 dtype × 三 split × softcap 开/关的 60 项公开回归；影响为所有引用该 Vector 的 512+64 非量化路径，192/128 和 INT8 算法不变，完整 MLA E2E 均运行。

先保留旧扩展、失败日志和同输入路径对照，再用仓库现有 `setup.py build_ext --inplace` 增量构建，核对实际受影响 TU 和新扩展路径/哈希。必跑：原失败节点与同输入 TND/mixed 双 dtype、metadata、单/自动/显式 split；针对根因的确定性公开回归；相关固定源对照、双数学 reference、边界及前后公开耗时检查；最终运行完整 MLA 和 R4 的普通 FA3 140 项选跑集合。重建后普通 FA3 结果也重新实测，不能继承旧扩展的通过记录。旧 269 passed + 1 failed 的中止结果仅用于定位，不作为完整验收；所有生产修改在最终完整测试前固定。

补充定位：完整回归在第 334 项检出 `window-softcap-single-paged_bsnd-compressed-bf16` 的 1 ULP 偏差；旧扩展同样失败。softcap 的 PV 使用已转为输入 dtype 的 P，原归一化分母却使用转换前的 P 总和，会放大近常量 V 的偏差。仅对非零 softcap，用固定源已有 RowSum 归约实际送入 Cube 的 P，并按同一 nUpdate 位修正累计分母；LSE、cap=0 源路径和原阈值不变。新增确定性近常量 V 的 30 项回归，验证原失败、单/多块、单/自动/显式 split、双 dtype 和五布局；重建后补跑相关源/数学/性能及完整集合。设备 7 后续被其他作业占用，复现改用空闲的同型号 910B3 设备 1，性能对照须保持前后同设备。

性能补充检查的依据：修复前后顺序采样出现明显差异，改为同 CPU/设备交替采样后平均比为 1.012591，未改动的普通 FA3 对照也慢 1.6%–4.2%，故不能据此断言实现无开销或性能达标。保留两轮数据，在生产实现不变的前提下，复用相同 60 个固定输入，对其中 50 个 cap=0 配置补测固定原生 CANN；10 个 softcap 配置无同义源，继续单列前后开销。先校验已有 native 包配方/哈希、真实分派和数值，再用既定 5 次预热、5×20 wall、R=1/4 交替采样；按真实 FD 分派与 split 语义确定适用集合，不能按耗时筛选。所有入口/R、原生 FD 单列项与退化数量均保存，平均门槛仍按 design 第 7 节。

组件性能复用已通过固定源/双数学的 36 个普通输入（双 dtype、三 mask、短/长 KV、多 M 块及 128 头），用归档驱动交替采 5×20 预分配 probe wall 和独立 5×10 profiler Kernel。保持同调度、单片与原缓冲；另外四个确定性源缺陷输入继续用于正确性，不把错误输出耗时计为同义性能。组件结果单列，不能替代公开 E2E 平均。

当前完成情况：用例为 1,578 项，完整 MLA 与普通 FA3 共 1,718 项正确性通过；固定源、确定性回归检错、覆盖及质量检查已完成。新选公开性能集合中，10 个同义自动 split 配置首轮平均比 1.034434，未达 ≤1；其余 40 项按预先定义的分派规则单列。该新集合不能替代 M17 的原始固定矩阵，也不能据此判定历史 0.726740/0.796747 已退化。

用户追问历史 0.7–0.8 的差异后，复核发现新集合只含压缩表示、默认 pack/margin、无 mask 的长 KV 自动 split；M17 调度集合的自动项使用显式 pack/margin 和 window，eager 还包含短 KV 单片与 prefill。补充对照直接恢复 M17 原始平均中的 20 个调度、40 个 eager 适用配置，使用归档的原输入/helper/入口/R；同时保留新集合的 10 个诊断配置。两扩展在同设备、同 CPU 上交替执行，每配置分别比较当前/修复前、当前/CANN、修复前/CANN，不混合不同集合的平均。native 包与历史分派原始证据复核身份，每个当前分配实际执行数值预检；5 次预热、5×20 wall、R=1/4 与原适用规则不变。新增诊断失败保留，性能结论以一致口径的对照为依据。

补充对照已完成：原调度/eager 矩阵保持通过，新增默认路径集合的差距在同场修复前基线已存在，不能写成本次数值修复造成的整体退化。所有 70 配置、前后扩展及原生源数值预检均执行，逐例/分段/输入哈希和原始样本保存。2026-10-19 用户明确确认记录该既有性能差距并提交本轮改动，按 design 第 7 节的 R5 单次例外收尾；该集合仍未达标。完成条件已满足，质量检查后只提交本步六个文件并停止，不扩展默认路径优化。具体结果和复现命令在 status 维护。

## R4：公开 E2E 测试整理（已完成）

用户于 2026-10-19 要求按仓库原有测试风格，仅新增一个 MLA 测试文件，并确认保留全部公开功能 E2E，移除 MLA 专用单元测试和迁移验收工具。以 `d433904` 为基线，将公开 API 的数值、布局、mask/split、空值/stride/长度、metadata 复用、生命周期、参数拒绝、fake/compile 与图重放集中到 `tests/test_flash_attn_npu_v3_mla.py`；重复的迁移阶段检查合并为参数化用例。删除 `tests/mla/` 和旧兼容验收入口；清理公共 conftest、README、文档及无头脚本对旧工具的依赖。加入既有全量 CI 的文件选项，并对非 910B/C 设备跳过 MLA 测试。生产 Python 仅修正 docstring 的测试路径；生产逻辑、C++、构建和 CATLASS 不变。

实施前保存旧 E2E 收集清单和能力映射于仓库外工作根的 `mla-test-cleanup/`。新文件使用直接 pytest 与仓库公共比较规则，不依赖 CANN 源仓、组件 probe 或本机 `/tmp/mla-*` 夹具。公开数值必须有独立 reference，重用/图/编译一致性不能单独替代数值判定；INT8 的既有数学限制须保留说明，不能放宽比较阈值来消除失败。

必跑检查：旧驱动 dry-run/collect 核对日常基线；新文件 `python3 -m pytest --collect-only -q tests/test_flash_attn_npu_v3_mla.py`，对照保留/合并/移除的覆盖目的；先实跑双 dtype、两种表示、五布局、INT8、fake/compile/图的代表及长 KV 成本边界，再固定实现运行新文件完整集合及普通 FA3/图回归。使用 910B 设备 7 和已验收扩展，先核对 Python/torch/torch_npu/CANN、芯片、扩展 SHA256 与生产源码身份；不因纯测试整理重建未变的扩展。继承 M21 的生产数值与性能记录，仅作生产基线，本轮测试结果另记，旧节点通过不能冒充新节点执行。

完成条件已满足：单个 MLA 测试文件可直接 pytest 运行，无旧工具导入或失效文档链接；完整公开功能集合与受影响普通回归通过。覆盖映射见 design 第 7 节，最新命令、耗时和证据见 status。质量检查后只提交本步改动并停止。

## 迭代与收尾规则

遵循 [AGENTS.md](../../AGENTS.md#一次工作只完成一个提交) 和 [design 第 7 节](design.md#7-验收口径)。实现前明确影响路径、必要用例、继承依据和完成条件；验证失败时保留交接，不提交为完成。测试整理后的入口为普通 pytest，只有一个 MLA E2E 文件，不恢复迁移阶段的独立测试框架。每成功完成五轮开发插入专门文档轮；文档轮不计开发轮数。一次提交完成后立即停止。
